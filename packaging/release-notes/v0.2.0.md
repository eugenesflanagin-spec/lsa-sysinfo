# Linux System Audit 0.2.0

Two more lines of the classic result window are now real readings instead of placeholders
(CPU FSB and North Bridge Clock), LSA has a full user guide that opens at the right section
from any value, and the command line now asks before it starts a run.

## What it is

LSA is a clean-room Linux implementation of AIDA64 Business's Cache & Memory Benchmark,
built to produce results 1:1 with the native Windows app. On the reference system
(Ryzen 7 7800X3D, DDR5-6000) every cell - memory read / write / copy / latency and
L1 / L2 / L3 - lands within about 3% of AIDA64, except L1 Read, which runs about 5% low
(see CHANGELOG.md). AIDA64 itself varies by a similar amount from run to run.

AIDA64 is FinalWire Ltd.'s product (https://www.aida64.com). Linux System Audit is not
affiliated with or endorsed by FinalWire and contains none of its code or data.

## What's new

**CPU FSB is measured (Linux).** LSA now works out the real reference clock from the CPU's
time stamp counter and its nominal frequency (TSC x 100 / ACPI CPPC `nominal_freq`). On a
board running its base clock at 105 MHz (ASUS "eCLK 105") the line now reads `105.0 MHz`
instead of a fixed 100. CPU Multiplier and DRAM:FSB Ratio follow it, for example
`DRAM:FSB 28.6:1` for DDR5-6000 at 105 MHz. CPUs without an invariant TSC or CPPC show
`100.0 MHz (nominal)`.

**North Bridge Clock (AMD Ryzen 7000 desktop).** The line shows the Infinity Fabric clock
(FCLK), e.g. `2133.0 MHz`, read-only from the PM table of the optional `ryzen_smu` driver.
Only the Zen 4 desktop table layout (version 0x540104) is read; without the driver, or on
other CPUs, the line says `n/a` and why.

**User guide, one click from every value.**
- PDF and HTML guide installed in `/usr/share/doc/lsa-sysinfo/`, with a menu entry
  **LSA User Guide (PDF)**: plain-English user guide, a section for every cell and system
  line, the command-line reference and a glossary.
- In the window: a **Guide** button; **F1** opens the section of the value under the mouse
  pointer; **right-click** any value -> *Open guide*. Hover a value for its name.
- On the command line: `lsa guide mem-latency` (or any item; `lsa guide --list` lists them,
  `--print` shows what would be opened).

**Command-line fixes.**
- `lsa cachemem --help` exits with code 0.
- A misspelled `--isa`, `--only`, `--tests` or `--mem-write` value now stops with a message
  listing the valid values, instead of silently running something else.
- `--mib` shows cache results in true GiB/s (divided by 1024, not 1000).

## Behaviour change: the command line asks first

`lsa cachemem` now asks `Start now? [y/N]` before it loads the CPU and memory, the same as the
window. **Scripts must add `--yes`** (or `-y`): without a terminal and without `--yes` it does
not start and exits with code 2. Example:

```sh
lsa cachemem --yes > result.txt
```

## Windows

- The installer and the portable zip now include `LSA-User-Guide.html`; the installer adds a
  Start-menu shortcut to it, and the window's **Guide** button and F1 open it.
- `lsa.exe guide` opens the HTML guide at its start (Windows does not pass the section on).
- CPU FSB shows `100.0 MHz (nominal)` and North Bridge Clock `n/a` on Windows: neither is read
  there.

## Install

**Arch Linux**

```sh
sudo pacman -U lsa-sysinfo-0.2.0-1-x86_64.pkg.tar.zst
# or from the AUR:  yay -S lsa-sysinfo
```

**Debian / Ubuntu**

```sh
sudo apt install ./lsa-sysinfo_0.2.0-1.deb13_amd64.deb        # or the .ubuntu24.04 file
```

**Fedora / openSUSE**

```sh
sudo dnf install ./lsa-sysinfo-0.2.0-1.fc44.x86_64.rpm
sudo zypper install ./lsa-sysinfo-0.2.0-1.tw.x86_64.rpm
```

**Any other distribution**

```sh
tar xf lsa-sysinfo-0.2.0-linux-x86_64.tar.gz
cd lsa-sysinfo-0.2.0-linux-x86_64
./usr/bin/lsa-gui                     # run in place, or install:
sudo cp -r usr/bin usr/share /usr/local/
```

`INSTALL.txt` in the tarball covers the menu entries and uninstalling.

**Windows**

Run `lsa-sysinfo-0.2.0-setup.exe` (installs for your user only, no administrator rights), or
unpack `lsa-sysinfo-0.2.0-win64-portable.zip` anywhere and start `lsa-gui.exe`.

Upgrading keeps your run history (`~/.cache/lsa/cachemem-history.txt`); its format has not changed.

## Requirements

- 64-bit x86 Linux with GTK 3, GLib and Cairo. Use the package for your distro; the generic
  `linux-x86_64.tar.gz` is built from the Ubuntu 24.04 package and needs glibc 2.38 or newer
  (check with `ldd --version`)
- Windows: 64-bit Windows
- `hwdata` or `pci.ids` for chipset names
- Optional: srs-sysinfo's `srs-root` cache for memory type / speed details
- Optional: the `ryzen_smu` kernel driver (AUR `ryzen_smu-dkms-git`) for North Bridge Clock
- Optional: `xdg-utils` to open the guide (Okular, Evince or Papers jump straight to the
  section; otherwise the HTML guide opens in the browser)

## Known limits

- Only the Cache & Memory Benchmark exists so far; the rest of AIDA64's features are planned
  (see CHECKLIST.tsv).
- L1 Read reads about 5% below AIDA64 on the reference system (documented in CHANGELOG.md).
- Results are tuned and checked on one AMD Zen 4 system; other CPUs may differ more.
- North Bridge Clock is read only on Ryzen 7000 desktop CPUs with `ryzen_smu` loaded.
- The benchmark loads every CPU thread and the memory bus for about 20 seconds. Run it on an
  otherwise idle machine, and never at the same time as another memory benchmark (for example
  AIDA64 under Wine) - both results will be wrong.
- Memory latency on Windows uses 4 KB pages unless "Lock pages in memory" is granted, so the
  Windows latency figure is higher than the Linux one.
